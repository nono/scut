# scut

`scut` is a command line client for the Shortcut REST API v4.
It prints JSON by default. It is made for scripts and coding agents.

## Install

```sh
mise use github:nono/scut
```

Releases are for Linux amd64 only. You can also build it with `make build`.
`scut worktree` needs git 2.36 or later.

## Log in

Create a v4 token at https://app.shortcut.com/settings/account/api-tokens.
A read-only token starts with `sct_r_`.

```sh
scut auth login < token.txt
```

The token comes from stdin. `scut` keeps it in the OS keyring.
The token holds the workspace name, so you do not set it.

Other ways to give the token, in order of priority:

1. `--token-file <path>`
2. the `SCUT_TOKEN` environment variable
3. `token_file` in the user config file
4. the OS keyring

Check it with `scut whoami`.

## Config

The user file is `~/.config/scut/config.toml` (or `$XDG_CONFIG_HOME/scut/config.toml`).
It holds your defaults:

```toml
team = "Software Dev"
state = "To Do"
owner = "@me"
requester = "@me"

[fields]
"Technical Area" = "Back end"
```

Other keys: `workflow`, `output` (`json` or `human`), `token_file`.
A `[profile.<name>]` table holds the same keys for a second workspace.
Pick it with `--profile <name>` or `SCUT_PROFILE`.

The repo file `.scut.toml` has the same keys, except `token_file`. No file accepts `token`.
`scut` looks for it from the current directory up to the git root.
A token in a repo file is an error.

Precedence: flag, then `SCUT_*` environment variable, then repo file,
then user file, then built-in default.
The environment variables are `SCUT_TEAM`, `SCUT_STATE`, `SCUT_WORKFLOW`,
`SCUT_REQUESTER`, `SCUT_OWNER`, `SCUT_OUTPUT` and `SCUT_FIELDS`.
`SCUT_FIELDS` has the form `Name=Value;Name=Value`. Each name in it
replaces that key of `[fields]`; the other keys stay.

## Use

```sh
scut usage                 # all commands
scut story usage           # the commands of one noun
scut story view 1234
scut story search 'owner:me state:"To Do"'
scut story create --name "Fix the login" --type bug
scut story update 1235 1236 1237 --parent 1234 # one change on several stories, in one call
scut doc view <doc URL> --out spec.md # write the markdown to a file
scut worktree 1234 --start # find or make the git worktree of the story, and start the story
scut spec updateStory       # method, path, parameters, body and response of a v4 operation
```

Use names, not IDs. A wrong name exits 3 and the error lists the valid names.
Searches and comment lists give 25 items. Use `--limit N` or `--limit all`. Lookup lists give all items.
Add `--human` for text output.

## Exit codes

| Code | Meaning |
| ---- | ------- |
| 0 | ok |
| 1 | other error |
| 2 | usage error |
| 3 | not found |
| 4 | auth error |
| 5 | Shortcut is unavailable (a write may have taken effect) |
| 130 | cancelled |

An error is one JSON object on stderr: `error`, `status`, `api`, `suggestion`, `valid`.

## Permission rules

Each write is its own subcommand. Thus a Claude Code rule such as `Bash(scut story comment:*)` allows comments, and no other write.

- Do not allow `scut api` or a group such as `scut story`: they include writes.
- A rule matches the start of the command. Put global flags after the subcommand: `scut --human story view` does not match `Bash(scut story view:*)`.
- A read-only token (scope `r`) also stops all writes.
- The skill's `allowed-tools` lists the commands with "yes" in the last column, so reads run with no prompt. It leaves out each command that writes anything other than the cache: to Shortcut, to the keyring, to a file at a path that you give (a `--out` flag), or `cache clear`. A new command with no ops annotation is left out too.

## Log

`scut` adds one JSON line to a local log for each run, to help debug failures and show how `scut` is used. The log is on by default. It stays on your machine: `scut` never sends it.

- **Location:** `$XDG_STATE_HOME/scut/scut.log`, or `~/.local/state/scut/scut.log`.
- **Records:** time, version, Claude Code session, directory, command, IDs, flag names, some flag values (`limit`, `comments`, `fields`, `format`, `depth`, `method`, `state`, `workflow`, `team`, `type`), duration, output size, exit code, and the method, path, status and duration of each HTTP try.
- **Does not record:** the token, story text, comments, search queries, or other flag values.
- **Exceptions:** an error message can quote your input or text from Shortcut (cut at 1 KB), and the log keeps the path that you give to `scut api`.
- **Size:** at 5 MiB, `scut.log` becomes `scut.log.1`, which replaces the old one. So the log is at most about 10 MiB. If that rename fails, `scut.log` stops at 10 MiB.
- **Stop it:** set `SCUT_LOG=off`.

```sh
jq -cR 'fromjson?|select(.exit!=0)|{t,cmd,exit,error}' ~/.local/state/scut/scut.log
```

## Development

```sh
make lint test
make live   # read-only smoke test on a real workspace
```

`make live` needs `SCUT_TOKEN` or `~/.config/shortcut-v4-token`, and `SCUT_LIVE_STORY`: the ID of a story with one attachment. It skips without them. The other `SCUT_LIVE_*` variables give the expected values; see `internal/live/live_test.go`. In CI they are repository variables, and the token is the secret `SCUT_LIVE_TOKEN`.
The Prism contract tests need Node 22 or later. `make test` installs Prism in `node_modules` with `npm ci`, at the version in `package-lock.json`. Without it, `go test` skips these tests; with `CI=true` they fail instead.
