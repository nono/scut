# `scut worktree` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `scut worktree <story>` finds or makes the git worktree of a story, and `--start` marks the story as started.

**Architecture:** A new package `internal/gitwt` runs the `git` binary and knows nothing about Shortcut. The command in `internal/cli/worktree.go` joins it with the API. The API part is lazy: no token is needed when the worktree or the branch exists and `--start` is not given.

**Tech Stack:** Go, cobra, `os/exec` with `git`, `httptest` through the existing `testapi` harness.

**Spec:** `docs/design/2026-11-05-worktree-design.md`

## Global Constraints

- Match a branch on `sc-<id>` with no digit after it.
- Sources in order: `worktree`, `local`, `remote`, `new`. Fetch only when no source matches, then check `remote` again.
- Base of a new branch: `origin/HEAD`, else `origin/main`. `origin` is the only remote.
- Exit codes: 2 for more than one match, a `--branch` not in the list, a `--branch` with no `sc-<id>`, a directory in use (empty or not), a prunable worktree, outside a git repo. 3 for a null branch name, a branch name with no `sc-<id>`, a workflow with no `started` state. 1 for a git failure, with git stderr in the message.
- Output keys: `story`, `branch`, `dir`, `created`, `from`, plus `started` with `--start`. `dir` is absolute.
- No API call and no token needed when a worktree or a branch matches and `--start` is not given.
- Comments, commit messages and docs follow ASD-STE100. No `feat:` prefixes. Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- The repo is public: no workspace slug, real names, UUIDs or story titles in tests or docs. Use story 1234 and the `acme` fixtures.
- Delete this plan file before merge.

## Review Focus

1. No token configured and a local branch exists: exit 0, JSON output, no HTTP request. Test in Task 2.
2. Run from a subdirectory of a worktree that is not main: the new directory is a sibling of the main worktree. Test in Task 1.
3. The story branch is checked out in the main worktree: `from: worktree`, `dir` is the main worktree. Test in Task 1.
4. `--dir` relative path: resolved against the current directory, printed absolute. Test in Task 2.
5. A detached-HEAD worktree or a bare entry in `git worktree list`: skipped, not an error. Test in Task 1.

### Task 1: package `gitwt`

**Files:**
- Create: `internal/gitwt/gitwt.go`
- Test: `internal/gitwt/gitwt_test.go`

**Interfaces:**
- Produces:
  ```go
  type Source string
  const (Worktree Source = "worktree"; Local Source = "local"; Remote Source = "remote"; New Source = "new")

  type Match struct {
      Branch   string // short name, without refs/heads/ or origin/
      Dir      string // only for Worktree
      Source   Source
      Prunable bool   // only for Worktree
  }

  type Repo struct{ Main string } // absolute path of the main worktree

  func HasID(branch string, id int64) bool
  func Open(ctx context.Context, dir string) (Repo, error)         // outside a repo: exit.Usagef("not in a git repository")
  func (r Repo) DefaultDir(id int64) string                         // filepath.Join(filepath.Dir(r.Main), "<id>")
  func (r Repo) Find(ctx context.Context, id int64) ([]Match, error) // matches of the first source that has any; nil when none
  func (r Repo) Fetch(ctx context.Context) error                    // git fetch origin
  func (r Repo) Base(ctx context.Context) (string, error)           // "origin/HEAD" when it resolves, else "origin/main"
  func (r Repo) Add(ctx context.Context, dir string, m Match, base string) error
  ```
  Each git failure returns `&exit.Error{Code: exit.Other, Msg: "git <args>: <trimmed stderr>"}`.

**Approach notes:**
- `Open`: `git -C dir rev-parse --path-format=absolute --git-common-dir`, then the first `worktree` line of `git -C <that> worktree list --porcelain`. Requires git ≥ 2.31 for `--path-format`.
- `Find` worktree source: parse `--porcelain` blocks; skip blocks with `bare` or `detached`; `branch refs/heads/X` gives the name; a `prunable` line sets `Prunable`.
- `Find` local and remote: `git for-each-ref --format=%(refname:short) refs/heads` and `refs/remotes/origin`; drop `origin/HEAD`; strip `origin/`. Sort names; remove duplicates.
- `Add`: Local → `git worktree add <dir> <branch>`. Remote → `git worktree add --track -b <branch> <dir> origin/<branch>`. New → `git worktree add -b <branch> <dir> <base>`.
- Test helper `newRepos(t) (origin, main string)`: `git init --bare -b main`, clone, one empty commit with `-c user.name=t -c user.email=t@example.com`, push. Set `GIT_CONFIG_GLOBAL=/dev/null` and `GIT_CONFIG_NOSYSTEM=1` with `t.Setenv`.

- Prunable: `&exit.Error{Code: exit.Usage, Msg: "the worktree of <branch> at <dir> is missing", Suggestion: "git -C <main> worktree prune"}`.

- Produces: `func startStory(ctx context.Context, d *deps, id int64) (started bool, err error)`. Ops annotation becomes `getStory,listWorkflowStatesWithinAWorkflow,updateStory,getWhoami`.

**Approach notes:**
- `GET stories/<id>` with `fields=workflow_id,workflow_state_id,owner_ids`.
- `GET workflows/<workflow_id>/states` with `fields=id,type,position` and `limit=100`. The nested states in `/workflows` are `WorkflowStateSlim` with no `type`, so the resolver cache cannot give it.
- Current state type `unstarted`: target is the `started` state with the lowest `position`; none → exit 3 `no started state in workflow <id>`.
- `owner_ids_add: [me]` only when `me` is not in `owner_ids`.
- One `PATCH stories/<id>` with the changes; no PATCH when there are none.
- On a `startStory` error after the git part: copy the `*exit.Error` (or wrap a plain error as code 1), set `Worktree` to the result, return it. The worktree stays.
