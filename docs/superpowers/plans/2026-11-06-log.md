# Run Log Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Each run of `scut` adds one JSON line of facts to a local, size-limited log that the user and Claude Code can read.

**Architecture:** A new package `internal/runlog` holds the line rules, the HTTP recorder and the file write. `cli.Execute` starts a `Recorder`, gives it to the HTTP clients through `Env`, and finishes it after the command. A failure of the log has no effect on the run.

**Tech Stack:** Go stdlib (`net/http`, `encoding/json`, `syscall.Flock`), cobra. No new dependency.

**Spec:** `docs/design/2026-11-06-log-design.md`

## Global Constraints

- Check with `make lint test`. `make lint` runs `deadcode -test`, so each new function must have a caller.
- Commit messages: a short description with a capital first letter and no final period. No Conventional Commits. No story prefix. End each with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Tests and fixtures use fake values only (`example-ws`, `Test User`). The repository is public.
- Use absolute paths in Bash commands. Use `git commit -F <file>` for a multi-line message.
- Text for humans follows ASD-STE100.
- Limits: file 5 MiB, `error` and `api` 1024 bytes, `http[].err` and flag values 200 bytes, `ids` and `http` 100 entries.
- Delete this plan before merge.

## Review Focus

1. A numeric argument that is not valid as a JSON number, such as `007`, or too large for 64 bits: the line must still be written. Test in Task 1.
2. An error with invalid UTF-8, or a cut in the middle of a character: the line must be valid JSON. Test in Task 1.
3. `XDG_STATE_HOME` is a regular file, or the log path is a directory: the run gives the same stdout, stderr and exit code. Test in Task 3.
4. `scut api 'stories/search?query=secret'`: the path is logged, the query is not. Test in Task 3.
5. A run that stops before a command starts (unknown subcommand, bad flag, no token): a line is still written, with the error. Test in Task 3.

### Task 1: Line rules and HTTP recorder

**Files:**
- Create: `internal/runlog/runlog.go`
- Test: `internal/runlog/runlog_test.go` (package `runlog`)

**Interfaces:**
- Produces:
  - `type Recorder struct` (unexported fields; a mutex guards the `http` entries)
  - `func Start(getenv func(string) string, now func() time.Time) *Recorder`. It returns nil when `getenv` is nil, when `SCUT_LOG` is `off`, or when `XDG_STATE_HOME` and `HOME` are both empty. It reads `CLAUDE_CODE_SESSION_ID`.
  - `type Result struct { Version, Dir, Cmd string; Args []string; Flags map[string]string; OutBytes int64; Exit int; Err error }`. `Flags` has the raw values. `Finish` applies the allowlist.
  - `func (r *Recorder) API(base http.RoundTripper) http.RoundTripper`
  - `func (r *Recorder) Files(base http.RoundTripper) http.RoundTripper`
  - `func (r *Recorder) Finish(res Result)`
  - `func Logged(flag string) bool`
  - All `Recorder` methods accept a nil receiver: `API` and `Files` return `base`, and `Finish` does nothing. A nil `base` means `http.DefaultTransport` at the time of the call.
  - `func (r *Recorder) encode(res Result) []byte`, unexported, gives the line with the final newline. `Finish` calls it, then `appendLine` of Task 2. In this task, `Finish` stops after `encode` is called, so that Task 2 adds the write.

- [ ] **Step 4: Implement `internal/runlog/runlog.go`**

The struct fields have the JSON names of the spec. `args_n`, `ms`, `out_bytes`, `exit`, `cmd` and `http[].s` have no `omitempty`. All others do.

- The round tripper records after `base.RoundTrip` returns and does not touch the request or the response body.

- [ ] **Step 3: Implement `appendLine`**

Algorithm:

1. `os.MkdirAll(dir, 0o700)`.
2. `os.Stat(path)`. If the size is at least `maxFile`, call `rotate`.
3. `os.OpenFile(path, O_APPEND|O_CREATE|O_WRONLY, 0o600)`, one `Write`, `Close`.

`rotate` opens the directory, and calls `syscall.Flock(fd, LOCK_EX|LOCK_NB)`. If it does not get the lock, it returns. If it gets the lock, it does `os.Stat` again, and does `os.Rename(path, path+".1")` only if the size is still at least `maxFile`. Flock on the directory means that no lock file stays on disk. A failure of `rotate` does not stop the write.
